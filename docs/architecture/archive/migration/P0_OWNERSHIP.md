# P0 Ownership & Compatibility Map (Capella Pro Notes)

This file documents the P0 stabilization decisions for the `notes` feature.
It is intentionally concise — use this as the single source of truth during P0.

## Canonical implementations (owned surfaces)

- `modules/` — canonical UI and feature module implementations (editor, list, sidebar).
- `store/` — canonical Zustand store implementation (`useNotesStore`).
- `lib/` — canonical helper utilities (text extraction, formatting, selectors).

## Compatibility / Deprecated shims (P0)

These folders are kept only for backwards compatibility during P0 and are marked with TODO/deprecation comments:

- `components/` — compatibility re-exports that forward to `modules/`. Do not add new implementations here.
- `state/` — compatibility re-exports that forward to `store/`. Do not add new implementations here.
- `utils/` — compatibility re-exports that forward to `lib/`. Do not add new implementations here.

Migration note: these compatibility folders will be removed or collapsed in P1 once callers are updated to import from canonical surfaces.

## Forbidden / discouraged patterns (P0)

- DO NOT call `useNotesStore.getState()` (Zustand imperative API) from non-React modules (editor extensions, utility modules, etc.).
  - Editor extensions must accept injected accessors (see `modules/editor/extensions/WikiLink.ts`).
- DO NOT add new deep imports under `@features/notes/.../modules/.../components` from external features. Prefer the feature barrel.
- Prefer the canonical import surface: `@features/notes` (feature barrel). Use named re-exports or the `Utils` / `Modules` namespaces where available.

## Short-term migration guidance

- When consuming helpers, prefer `import { generateFallbackTitle } from '@features/notes'`.
- When consuming the store, prefer `import { useNotesStore } from '@features/notes'`.
- For editor extensions, inject runtime dependencies from the React initialization layer (example: `useEditor` injects `getNotes` into `WikiLink`).

## Where to look for changes

- Compatibility shims with deprecation comments:
  - `state/index.ts`, `state/notes.store.ts`
  - `utils/notes.helpers.ts`
  - `components/index.ts`, `components/editor/index.ts`
- Injection example:
  - `modules/editor/extensions/WikiLink.ts` (now requires/accepts `getNotes`)
  - `modules/editor/hooks/useEditor.ts` (injects `getNotes` accessor)

## Next steps (P1)

- Migrate all internal imports to `@features/notes` named exports or namespaces.
- Remove compatibility shims after upgrades.
- Add ESLint rules to forbid deep imports and disallow `useNotesStore.getState()` in non-React files.
